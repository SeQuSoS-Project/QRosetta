Understanding QRosetta

QRosetta runs one quantum circuit across many simulator backends under a common contract and reports, transparently, where they agree and where they differ.

What QRosetta is (and is not)

You give QRosetta a single OpenQASM 2.0 circuit. It dispatches that circuit to a fleet of quantum-simulator backends spanning major SDKs — including Qiskit (Aer), Cirq (and qsim), qibo, PennyLane (default and lightning), Qulacs, QuEST, quimb, myQLM, PyQuil, Qrisp, cuQuantum, and TorchQuantum, several of which are driven through pytket/TKET — each behind the same request/response contract. It then compares their outputs and classifies every pair of backends by whether they agree, and if not, what would explain the difference.

Academic-integrity scope. QRosetta performs agreement analysis, not formal verification. It has no ground-truth oracle: it cannot tell you which backend is “correct,” only whether backends agree and which known convention (if any) explains a difference. Every transform it applies during analysis is reported with its numerical effect and provenance — QRosetta never silently reverses bit order, aligns phases, or otherwise “repairs” a backend’s output.

Quickstart

  1. Enter an OpenQASM 2.0 circuit, or generate a preset (GHZ, Bell, QFT, Grover, Bernstein–Vazirani, VQE, random) or pull one from a benchmark suite.
  2. Open the Config drawer to choose which backends to run, the timeout, optimization level, sampling seed, and (optionally) agreement thresholds.
  3. Pick a run mode — statevector or measured — and run.
  4. Read the report tabs: Summary, Performance, Resources, Divergence, Agreement, Artifacts, and Raw.
Tip. The Playlist lets you queue several circuits and run them as a batch; you can import/export a playlist as JSON for repeatable suites.

Run modes

ModeWhat each backend returnsHow QRosetta compares
Statevector The full output state amplitudes (exact; no sampling). Fidelity and relative phase between state pairs. Exact and deterministic — no seed needed.
Measured A histogram of measurement outcomes over a chosen number of shots. Jensen–Shannon divergence and Hellinger distance between count distributions, plus a shot-noise-aware statistical test.

Statevector runs are limited to smaller qubit counts than measured runs, because a full statevector grows as 2n. When a circuit exceeds a backend’s limits, that pair is reported as not comparable rather than guessed at.

The explained-cause agreement taxonomy

Two correct simulators can produce different-looking outputs for benign reasons — most commonly a different qubit-ordering convention (endianness) or an unobservable global phase. QRosetta’s core idea is to label each backend pair by the least transform that explains their difference, over a fixed, registered lattice, and to report that transform’s numerical effect explicitly.

Every transform is an explicit analysis mode. When a pair is labelled “after bit reversal,” the report also shows the raw metric and the post-transform metric, so you can see exactly what the transform changed. Transforms are never applied silently to the stored native outputs.

The shot-noise-aware statistical test

In measured mode a fixed distance threshold is only a heuristic — with few shots, two identical distributions can still look far apart purely from sampling. Alongside the descriptive JS/Hellinger label, QRosetta therefore reports a shot-noise-aware test:

  • A chi-square and a G-test of homogeneity between the two count distributions;
  • Benjamini–Hochberg (FDR) correction across the family of pairwise comparisons;
  • Effect size (total variation, Cramér’s V) and a prospective power estimate.

This yields a verdict — consistent, distinguishable, inconclusive_low_shots, or ambiguous — that runs in parallel with the descriptive label and never overrides it. It answers “is this difference statistically significant?”, which a fixed threshold cannot.

Reproducibility

Every measured run is reproducible by construction:

  • Seeds are never unrecorded. Set a sampling seed in the Config drawer for an exact replay, or leave it empty — QRosetta then generates a seed and records it in the report. No run is ever un-seeded. (Statevector mode is exact and needs no seed.)
  • Executed versions are captured. Each backend reports the exact SDK versions it ran, as ground truth, into the report’s provenance.
  • Exportable provenance. Reports can be exported as an RO-Crate that conforms to the Process Run Crate profile, packaging inputs, per-backend results, agreement evidence, and provenance as a FAIR, citable bundle.

Honest limitations

QRosetta is deliberately explicit about what it does not claim:

  • Agreement is not correctness. Backends agreeing does not prove they are all right; a backend differing does not prove it is wrong. There is no oracle.
  • Measured thresholds are heuristic. The default JS/Hellinger cut-offs are configurable and shot-count dependent; treat the statistical test as the rigorous companion.
  • Permutation search is bounded. Exhaustive qubit-permutation matching is capped (≤ 6 qubits); larger cases report the cap rather than guessing.
  • A “residual disagreement” is a starting point, not a verdict. It means no registered convention explained the difference — the cause still needs investigation (an unregistered convention, an environment limit, or a genuine defect in a backend or its adapter).

FAQ

Why would two correct simulators disagree?

Most often because of a convention, not an error: different qubit-ordering (endianness) or an unobservable global phase. QRosetta’s taxonomy is designed to name exactly these causes so a benign convention difference isn’t mistaken for a defect.

Is a “distance exceeds threshold” pair a bug?

Not necessarily. It means the difference survived every registered transform and (in measured mode) may be statistically significant. That warrants investigation — the cause could be an unregistered convention, a resource limit, or a genuine defect in a backend or in its adapter. QRosetta surfaces the evidence; the diagnosis is yours to make.

Does QRosetta modify a backend’s output?

No. Native outputs are stored as returned. Bit-reversal, phase alignment, and permutation are analysis modes reported with their numerical effect — they are never written back over the native result.

QRosetta is a research tool for cross-simulator agreement analysis. It reports native outputs faithfully and labels every transform explicitly. It is not a formal-verification system and has no ground-truth oracle.
