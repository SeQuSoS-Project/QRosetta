# Risk register for v2.0.0

Version 1, 2026-10-28 (task V0 of `docs/plans/2026-10-28-verification-campaign.md`, which is not tracked).
Sources: the wiring map's ranked list of untested failure modes (WM#n), the scientific V&V research report
(SCI) and the QA and security research report (QA), all in the private audit notes of 2026-10-28. The test
plan, exit criteria and threat model are in `test-plan.md` next to this file.

## Scales

- Likelihood (L): 1 = needs an unusual setup or a deliberate attacker; 2 = plausible in normal use of
  v2.0.0 within a year; 3 = expected in normal use (any restart, rebuild, long download or image skew).
- Impact (I): 1 = inconvenience, cosmetic; 2 = lost work, denial of service, a stated invariant broken
  without a wrong result; 3 = wrong scientific result, security breach or data loss.
- Score (S) = L x I. Effort goes in score order; within a score, impact 3 first.
- Covered by: a verification task (V1-V9), a polish task (A1-A13, B1-B4, C1), an existing test (path from
  the repository root), or "accepted: reason". Several entries mean each covers part of the risk.
- Owner: "yes" where a decision or an action only the owner can take is needed to close the row.
- Status: "open" until the covering test has run and passed or the acceptance is signed; "partly covered"
  where existing tests cover part of the risk and the rest is open; "covered" once the covering tests have
  run and passed. Updated 2026-10-30 from the task reports summarised in `completion-report.md`; an
  acceptance still needs the owner's signature.
