# API image on Python 3.12, 2026-10-21

Question: can the API image (`rosetta-api/Dockerfile`, python:3.10-slim) move to python:3.12-slim with the same lock file, without changing the circuit text the API dispatches or the analysis reports it writes? Runner and compiler images were not touched.

Code under test: commit bb31885 (branch harness-speed), mounted read-only into both images. Scripts: `scripts/py312_check/`. Small result files: `scripts/py312_check/results/`.

`Dockerfile.py312` differs from `Dockerfile` in the `FROM` line only. Every locked package installed from a cp312 (or pure-Python/abi3) wheel; the only wheel built locally was `qrosetta_commons`. No version was changed.

### pip freeze

Five packages differ because the reference image was built before the lock's patch upgrades on harness-speed (0855a54), not because of Python:

| Package | 3.10 image | 3.12 image (= lock) |
|---|---|---|
| anyio | 4.14.1 | 4.14.2 |
| certifi | 2026.6.17 | 2026.10.19 |
| pyasn1 | 0.6.3 | 0.6.4 |
| requests | 2.32.3 | 2.33.1 |
| urllib3 | 2.7.0 | 2.8.0 |

None of them is imported by the circuit preparation or the analysis. numpy 1.26.4 (bundled OpenBLAS 0.3.23.dev), scipy 1.14.0 and pytket 1.33.0 are the same in both.

One difference is caused by the move. `qwasm==1.0.1` depends on `setuptools` with no version bound, and the lock does not pin setuptools. python:3.10-slim ships setuptools 79.0.1, which satisfies it; python:3.12-slim ships none, so pip installed the newest release, setuptools 84.2.1. A 3.12 build therefore installs whatever setuptools is current on the build day. (`pip freeze` on 3.12 also lists setuptools, which it hides on 3.10.)

## Equivalence

Both images ran the same scripts on the same mounted tree, 2 CPUs and 4 GiB each.

### Analysis

`dump_analysis.py` builds the counts and statevector corpora of `scripts/harness_bench/equivalence.py` (seed 20261021): 200 counts cases and 150 statevector cases, covering every shape listed in `scripts/harness_bench/README.md`. Per case it writes the permutation search of the first four backends against every backend (7,498 searches in total) and the whole `create_counts_report` / `create_divergence_report`, as `json.dumps(sort_keys=True, default=repr)`.

Result: the two 33,247,648-byte files are identical (sha256 fc435268…afab07). 350 cases, 0 differences.

### Circuit preparation

`dump_prepare.py` runs `prepare_statevector_dispatch` and `prepare_measured_dispatch`, with `apply_preprocessing` True and False, on 327 files under `rosetta-api/benchmarks/` (269 MQT Bench, 58 QASMBench), the 4 files in `rosetta-api/circuits/`, and the 8 algorithm templates generated at 2, 3, 5, 8 and 12 qubits (40 texts, also recorded). Each output holds the dispatched text and the `api_preprocessing_applied` notes, or the exception type and message.

Result: the two 215,818,644-byte files are identical (sha256 8143cd09…de02ca8). 364 sources prepared, 1,456 calls, 0 differences. Both images recorded the same 20 refusals and the same 7 skips:

- 16 `StatevectorIncompatible` (statevector mode, both flags) for 8 QASMBench files with mid-circuit measurement, reset or `if`: bb84_n8, cc_n12, inverseqft_n4, ipea_n2, qec_sm_n5, seca_n11, shor_n5, square_root_n18.
- 4 `RuntimeError: Circuit does not contain unit with id: q[0]` from pytket for QASMBench vqe_uccsd_n4 and vqe_uccsd_n6 with preprocessing on (both modes).
- 7 files larger than 130,000 bytes were skipped in both: MQT grover-noancilla n18–n19 and grover-v-chain n18–n22. A first run without the cap filled the 4 GiB container on grover-noancilla_n18. grover-noancilla_n17 (123 kB) took 153 s on Python 3.12; from n10 to n17 the time grew 1.3–2× per qubit (2.6 s at n10).

The last two items behave the same on both versions. They are listed in the findings below.

### Unit suite

`unit_suite.sh` copies the tree into the container's throwaway layer, installs `rosetta-api/tests/requirements.txt` (pytest 8.2.2, pytest-asyncio 0.23.7, pytest-xdist 3.6.1, hypothesis 6.112.1) and runs `pytest -q -n 4 -p no:cacheprovider tests/unit`.

| Run | 3.10 | 3.12 |
|---|---|---|
| 1 | 1430 passed, 232 skipped | 1430 passed, 232 skipped |
| 2 (`-rs`) | 1430 passed, 232 skipped | 1430 passed, 232 skipped |

The skip lists are identical: 128 parity and harness tests need node, which the API image does not have; 12 need Qiskit; 1 has no request body. CI's 3.12 job covers the node tests outside the image.

Two earlier attempts are not counted. With the tree mounted read-only, 136 tests failed in both images on `OSError: Read-only file system: './data'`. With `DATABASE_URL` pointing all four xdist workers at one SQLite file, one 3.10 run failed at collection with `table saved_circuits already exists` (the workers ran `create_all` on the same file at once); the 3.12 run beside it passed. Neither depends on the Python version.

### Import time and memory

`import_bench.py`: five `python -c "import main"` processes per image, peak RSS from `wait4`. The repository modules are read from the mount with `PYTHONDONTWRITEBYTECODE=1`, so they are compiled from source on every run in both images.

| Round | 3.10 median s (5 runs) | 3.12 median s | 3.10 peak RSS MiB | 3.12 peak RSS MiB |
|---|---|---|---|---|
| 1 | 1.650 | 1.689 | 224.8 | 236.2 |
| 2 | 1.448 | 1.528 | 224.8 | 236.1 |

3.12 imports 2–6 % slower and holds 11.4 MiB more at peak.

### Analysis speed

Not part of the brief; measured because the analysis runs inside the API's request path. `pinned_bench.py` runs `scripts/harness_bench/bench.py` (5 repeats) with the process pinned to CPU 4, a P-core; rootless podman cannot pin a container, and an unpinned first attempt varied by up to 2.3× between rounds on 3.12. Two rounds per image, alternating; 20 samples per case and image.

## Recommendation

Move the API image to Python 3.12. Every output inside the scope of the petri-dish rule was byte-identical: 350 analysis cases (7,498 permutation searches) and 1,456 preparation calls, with the same refusals. The unit suite gives the same result on both versions. Python 3.10 reaches end of life this month (PEP 619), which `docs-audit/2026-10-21-dependency-audit.md` already notes. The cost is 9–14 % on statevector analysis and 11 MiB at import, against a 2 GiB API container.

Pin setuptools in `rosetta-api/requirements.lock` in the same commit. Without the pin, the 3.12 image installs the newest setuptools on each build. 84.2.1 is the version these tests ran with.

## What else changes if adopted

- `rosetta-api/Dockerfile`: replace the `FROM` line with the one in `Dockerfile.py312`, then delete `Dockerfile.py312`.
- `rosetta-api/requirements.lock`: add `setuptools==84.2.1`. `exceptiongroup==1.3.1` is needed only below 3.11 but does no harm.
- `.github/workflows/ci.yml`: the `unit-tests` matrix stays `["3.10", "3.12"]`, because `shared/qrosetta_commons` also runs in the 3.10 runner and compiler images, which keep 3.10. The comment "3.10 matches the python:3.10-slim API image; 3.12 is an upper bound" becomes wrong: 3.12 is then the API's version and 3.10 is the runner images' version.
- `CLAUDE.md` does not name the API's Python version, so it needs no edit. `CONTRIBUTING.md` line 261 uses `python:3.10-slim@sha256:...` as an example for runner images and can stay.
- `scripts/harness_bench/LEDGER.md` says timings were taken in the API image on Python 3.10.20. Entries made after the move must name 3.12, and earlier timings cannot be compared with later ones without accounting for the slowdown above.
- `docs-audit/2026-10-21-concurrency-audit.md` says "the API and runner images use 3.10". It is dated and can stay as written.
- The API's own Python version is not recorded in reports or crates (`runtime_environment` is filled by runners only), so reports made before and after the move can be told apart only by the API image's `git_sha`.
- Rahti: `scripts/rahti_push.sh` builds and pushes the API image as before; no manifest names the Python version.

## Findings outside the question

These behave identically on 3.10 and 3.12.

- With preprocessing on, the pytket round-trip of the bundled QASMBench `vqe_uccsd_n4.qasm` and `vqe_uccsd_n6.qasm` raises `RuntimeError: Circuit does not contain unit with id: q[0]`, so both circuits cannot run with preprocessing.
- Preparing MQT grover-noancilla_n17 took 153 s, and n18 reached the 4 GiB container limit, in the two pytket round-trips with preprocessing on (statevector and measured). The API container has 2 GiB, so submitting the bundled Grover circuits from about 17 qubits up with preprocessing on may get the API worker OOM-killed. This was not tried against a running API.
- With a shared `DATABASE_URL`, xdist workers can race on `create_all` (above). The CI job uses the default `./data` path, which all workers share as well.
