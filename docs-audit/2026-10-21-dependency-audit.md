# Dependency and image audit, 2026-10-21

Python dependencies of every image were checked with pip-audit 2.10.1 (PyPI advisory service) using `pip-audit -r <file> --no-deps --disable-pip`. Each `requirements.lock` is a full `pip freeze` of its image and is the file the Dockerfile installs, so the lock results are what ships; each `requirements.txt` was audited too, and its findings are a subset of the same image's lock findings in every case. Severities are the GitHub advisory ratings read from OSV. Dockerfiles were read against CLAUDE.md §8.

Not covered: OS packages in the base images (no image scanner is installed and images were not built or pulled), the two nginx images (no Python dependencies), and `shared/` on its own (its `setup.py` declares no dependencies; it runs on whatever each image installs).

### fastapi and starlette: not upgraded

fastapi 0.115.0 requires `starlette<0.39`, so all seven starlette 0.38.6 advisories need a fastapi change.

- fastapi 0.115.14 (the last release of the same minor) allows starlette 0.46.2. That closes PYSEC-2026-1943 (high, multipart DoS) but opens PYSEC-2026-1942 / CVE-2025-62727 (high, quadratic `Range` header handling in `FileResponse`, affecting 0.39.0 to 0.49.0). The API serves `index.html` through `FileResponse` and mounts `StaticFiles`, and the Rahti route reaches the API without nginx, so this trade was dropped.
- Closing all seven needs starlette 1.3.1, which needs fastapi 0.133 or later (0.130 to 0.132 cap starlette below 1.0). A trial in the scratch venv with fastapi 0.133.1, starlette 1.3.1 and its new dependency `annotated-doc` 0.0.4 gave the same unit results as the baseline (1592 passed and the flaky VmHWM test failed once), and a TestClient smoke run of `GET /config`, `GET /openapi.json`, register, `/auth/token` (urlencoded and multipart), `GET /auth/me` and `GET /js/main.js` returned the expected codes. `/openapi.json` changed in 98 diff lines: the password field gains `format: password`, the `grant_type` pattern becomes `^password$`, and `RunHistoryResponse` is no longer split into `-Input`/`-Output` schemas. Starlette 1.x also warns that `starlette.testclient` with `httpx` is deprecated. This is a framework upgrade of 18 fastapi minors and one starlette major, so it is left for an owner decision.

Reachability of the starlette advisories: `/auth/token` reads `OAuth2PasswordRequestForm`, which parses urlencoded and multipart bodies (PYSEC-2026-1943, -1941, -249). The 1 MB body middleware and nginx's 5 MB cap bound the body size. PYSEC-2026-2281 needs a Windows host. PYSEC-2026-2280 needs `HTTPEndpoint`, which the API does not use.

## Dockerfiles against CLAUDE.md §8

All 27 Python images create `appuser`, `chown` the app directory and end with `USER appuser`. No runner or compiler Dockerfile has `EXPOSE`, and `docker-compose.yml` publishes a port only for nginx (`80:80`). Every `FROM` is pinned by digest. No final image installs curl or wget; staq, Quartz and Synthetiq install curl in their build stage only, and download a tarball checked against a recorded sha256.

## Other findings

- Runner and compiler Job pods use the namespace's `default` service account with its token mounted. `_build_job_spec` in `services/dispatcher_k8s.py` sets neither `service_account_name` nor `automount_service_account_token`, and `infra/rahti/rbac.yaml` binds the `job-manager` Role (create, delete, patch Jobs; read pods and events) to `default`, which the API deployment also uses. Code execution inside a runner, which parses user QASM with third-party SDKs, would therefore be able to create Jobs in `qrosetta`, including pods that mount `rosetta-secrets`. Runners need only S3 credentials, which they get from environment variables. `automount_service_account_token=False` on the Job pod spec would remove the token; a dedicated service account for the API would keep `default` without Job rights. Not changed on this branch.
- CI installs `rosetta-api/requirements.txt`, while the API image installs `requirements.lock`, so CI resolves transitive dependencies freshly and tests a different set from the one that ships. CI also does not install qiskit, so the five qiskit-dependent tests above would fail there; I did not check the CI run history.
- No dependency audit runs in CI. A pip-audit step on `rosetta-api/requirements.lock` would need an ignore list for the advisories above that have no compatible fix.
